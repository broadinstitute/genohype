# Genohype maintainers

This file identifies people with repository-level maintenance responsibility. It intentionally distinguishes software maintainers from domain reviewers, standards advisers, downstream users, and institutional leadership.

## Maintainer responsibilities

Maintainers are expected to:

- keep the supported build and release paths reproducible;
- review contributions or obtain appropriate specialist review;
- maintain security reporting and dependency-triage processes;
- document compatibility, experimental features, and known limitations accurately;
- preserve authorship and review history when integrating contributions; and
- record consequential repository and release decisions in public issues, pull requests, or documentation.

Maintainers are not expected to be the sole scientific authority for every change. Annotation, genomic representation, quality-control, standards, security, and benchmark claims may require named domain review before merge.

## Domain review

Domain reviewers and advisers are invited for specific changes based on expertise and availability. They are not Genohype maintainers unless listed above, and their participation should not be represented as endorsement of unrelated project decisions.

Names will be added as standing reviewers or advisers only with the person's consent and an agreed description of the role.

## Changes to maintainership

A maintainer change requires the person's explicit consent and a public pull request updating this file. The pull request should describe the proposed responsibilities and must be approved by the current maintainers.

A maintainer may step down at any time. Maintainer entries should reflect current responsibility rather than honorary affiliation.
